# 桌面挂件素材清单

> 出图前先看这份。**结论先行：内置角色已经是手写 SVG 的小蓝，零素材就能跑。**
> 下面这张表只在你想**换成自定义角色图**（或做桌面外壳图标）时才需要准备。

本文所有规格都对着 [lib/client.js](../lib/client.js) 与 [desktop/main.js](../desktop/main.js) 的当前代码写，
不是通用建议。标了「代码位置」的都能自己点开核对。

## 一、速查表

| 素材 | 必须? | 格式 | 关键规格 |
|---|---|---|---|
| 角色静图 | **✅ 必须** | PNG-24 + Alpha | **1024×768 母版（4:3）**、透明底、主体占 78–86%、头朝左、≤1.5MB |
| 角色动图 | ⭐ 可选升级 | 动态 WebP（首选）/ GIF | 8–24 帧、8–12 fps、无缝循环、小幅局部动作 |

| macOS 图标 | 出 mac 包时 | .icns | 512 / 1024 |
| 安装包侧栏图 | 做安装包时 | BMP | 164×314 |

## 二、角色图（唯一必须的素材）

### 2.1 代码怎么读它

| 约束 | 值 | 代码位置 |
|---|---|---|
| 接受的 MIME | `image/png` `image/gif` `image/webp` `image/jpeg` | [client.js:604](../lib/client.js) |
| 体积上限 | 1.5 MB，超出直接拒绝并提示 | [client.js:567](../lib/client.js) |
| 存储 | base64 data URL → `localStorage["dsh-handsome-fish:art"]` | [client.js:565](../lib/client.js) |
| 渲染 | `<img>` + `object-fit:contain`，装在 224×168 的舞台里 | [client.js:340](../lib/client.js) |

### 2.2 ⚠️ 画布比例：用 4:3，不要用正方形

舞台是 **224×168 = 4:3**（[client.js:31-32](../lib/client.js)），
图片只受 `max-width/max-height:100%` 约束、按自身比例缩放：

| 原图 | 实际显示 | 后果 |
|---|---|---|
| 1024×1024 正方形 | 168×168 | 宽度浪费 25%，角色白白变小 |
| **1024×768（4:3）** | **224×168** | **正好铺满** |

（上表按 1024 长的母版举例；换成 512×512 / 512×384 结论完全一样 —— 决定显示的只有**比例**，不是像素数。）

默认形象的 SVG `viewBox` 是 `240 180`，同样是 4:3（[client.js:419](../lib/client.js)）。
**用 4:3 出图，换图后大小才能和默认形象完全一致。**

> 📌 [character-spec.md](character-spec.md) 里写的「正方形 512×512」是在舞台比例核对之前定的，
> **以本文为准**。该文件里的 AI 生图提示词、抠图后处理步骤仍然有效，可以继续用。

### 2.3 硬指标

| 项 | 要求 | 为什么 |
|---|---|---|
| 格式 | PNG-24 + Alpha | JPG 没有透明通道，在深色界面上就是一块白方块 |
| 背景 | 完全透明 | 不是白底、不是灰底、不是棋盘格 |
| 画布 | **1024×768**（4:3），压体积时降到 512×384 | 见 2.2 / 2.3.1 |
| 主体占比 | 外接矩形占画布 **78%–86%** | 留白过多 → 显得很小；贴边 → 浮动时容易被裁 |
| 底部留白 | **6%–8%** 透明边 | 内置浮动动画（`hf-bob`）会让它上下晃 |
| 朝向 | **头朝左** | 贴到屏幕左侧时整体水平镜像，所以只需出一张朝左的 |
| 体积 | ≤ 1.5 MB | 存储是 base64，还会再膨胀约 1/3 |
| 分辨率 | 512×384 起步，1024×768 最稳 | 见 2.3.1 —— 取决于你要不要在最大缩放下还保持锐利 |

### 2.3.1 分辨率该出多大

舞台基准 224×168 CSS px，角色大小可在 **60%–160%** 之间调（[client.js:31](../lib/client.js) 与设置菜单）：

| 显示场景 | 需要的物理像素 | 512×384 够吗 |
|---|---|---|
| 100% 大小 + 1× 屏 | 224×168 | ✅ 绰绰有余 |
| 100% 大小 + 2× 屏 | 448×336 | ✅ 够 |
| **160% 大小 + 2× 屏** | **716×538** | ❌ 会被放大 1.4×，轻微发软 |

**建议**：出 **1024×768**（4:3）母版，需要压体积时再降到 512×384。
1024×768 的 PNG 只要主体占比正确、背景干净，通常远在 1.5MB 以内；
真超了就降到 768×576 —— 不要为了压体积牺牲到 512 以下。

### 2.4 不要画进图里的

| 别画 | 原因 |
|---|---|
| 地面投影 / 接触影 | `.hf-art` 没有影子元素，CSS 只叠了一层 `filter:drop-shadow`。你烤进去的接触影会跟着浮动动画一起上下晃，反而假 |
| 边框、文字、水印、logo | 挂件最小时只有 134×101 CSS px，缩放后必糊 |
| 大幅位移的动效 | 整体浮动由代码的 `hf-bob` 负责，图里再做会打架 |

### 2.5 动图（可选，但效果最好）

| 项 | 建议 |
|---|---|
| 循环 | **无缝**，首尾帧能自然衔接，否则每次循环「抖」一下 |
| 帧数 | 8–24 帧 |
| 动作 | 尾鳍摆动 / 眨眼 / 腮部呼吸 / 嘴开合，**四选一即可**，只做小幅局部动作 |
| 帧率 | 8–12 fps 就够，挂件是氛围物件不是游戏 |
| 体积 | 最容易超限。优先**减帧数**、**缩到 384×288（保持 4:3）**，不要靠压色调凑 |

> 静态图完全可用 —— 挂件会给它加整体浮动动画。动图的价值只在于尾巴/眼睛是活的。

### 2.6 想要「帅 / 可爱」双形态？

做不到「一张图切换」。自定义图会把墨镜开关**置灰**（[client.js:592-599](../lib/client.js)），
而且当前只支持一张图（单个 `ART_KEY`）。要双形态必须出**两张**图 + 改代码。

## 三、桌面级外壳（`desktop/`）的图标素材

现状：`desktop/main.js` **没设 `icon`、没有托盘、没有 electron-builder 配置**，
所以下面这些是「接下来要用」而不是现在就在用。

| 素材 | 格式 / 规格 | 用在哪 |
|---|---|---|
| 应用图标 | **.ico**，内含 16/24/32/48/64/128/256 多尺寸 | `BrowserWindow.icon`（任务栏 / Alt-Tab） |
| 托盘图标 | **PNG** 16×16 + 32×32(@2x)，透明底、高对比 | 桌宠通常靠托盘退出/唤出 —— 目前还没做 |
| 可执行文件图标 | .ico，≥ 256×256 | `electron-builder` 打包时 |
| macOS 图标 | .icns（512 / 1024） | 只在要出 mac 包时 |
| 安装包图 | NSIS `installerIcon`（.ico）+ `installerSidebar`（**BMP 164×314**） | 只在做安装包时 |

> **应用图标 ≠ 角色图。** 角色是内容，图标是软件标识。
> 可以复用同一个鱼头，但**必须在 16px 下仍能看清轮廓** —— 直接拿角色立绘缩小只会糊成一团，
> 需要单独画一版「简化大头」（去掉细节、加粗描边、提高对比）。

## 四、明确**不用**准备的

| 不用准备 | 原因 |
|---|---|
| **音频文件**（wav/mp3） | 4 种音效全是 Web Audio 现场合成，见 [README.md:44-50](../README.md)。这还顺带绕开了「下载管理器抢走挂件音频请求」的坑 |
| 字体文件 | 菜单与气泡走系统字体栈 |
| 背景图 / 底纹 | 挂件是透明层，没有底板 |
| 精灵图 / 序列帧图集 | 当前 `renderCharacter()` 不解析 |
| SVG 角色 | 默认形象本身是内联 SVG，但上传通道不收 `image/svg+xml` |
| JPEG | 代码 `accept` 里虽然有，但没有 alpha，传进去就是深色界面上一块白方块 |

## 五、最小可用清单

今天就想看到效果，只需要这一个文件：

| # | 文件 | 规格 |
|---|---|---|
| 1 | `fish.png` | 1024×768（4:3）、透明底、主体占 80%、头朝左、≤1.5MB |

接进去：右键鱼 → **换个角色图** → 选中。
换回默认：右键 → **默认角色**（会清掉 `localStorage["dsh-handsome-fish:art"]`）。

再补一个 `.ico` 就能给桌面外壳一个正式图标。

## 六、验收清单

传进去之后对照检查：

- [ ] 深色界面下**没有白边 / 灰边**（AI 抠图的典型残留）
- [ ] 大小和默认形象相当，不显得过小（说明留白过多）
- [ ] 浮动到最高点时，鳍和尾巴没被切掉
- [ ] 拖到屏幕左侧时镜像正常（朝右看），形状不别扭
- [ ] 点一下有 Q 弹挤压（效果作用在容器上，与素材无关，但能看出是否贴边）
- [ ] 台词气泡在角色上方居中，没有压住角色的头
- [ ] 换成动图后，循环处不「抖」

## 附：本文的验证边界

2.2 的比例结论是从 CSS 与 DOM 结构推导的（`.hf-art` 是 `display:flex` + `align-items:flex-end`，
`.hf-img` 只有 `max-width/max-height:100%` + `object-fit:contain`，舞台 224×168），
**不是 headless 浏览器像素实测**。

> 🔧 **更正（2026-10-15）**：本节原本写着「Chrome 在 DSH 沙箱内无法启动（mojo 命名管道被拒绝）」
> —— 该说法**不成立**。同一会话里 headless Chrome 被稳定调用了几十次，产出了
> [../scripts/selftest-desktop.mjs](../scripts/selftest-desktop.mjs) 的全部自检结果与
> [shots/](shots/) 下的全部截图（形式：`chrome --headless=new --disable-gpu --no-sandbox …`）。
> 会卡住的是 **Electron 应用**（主进程停在 `app.whenReady()` 之前，见
> [../desktop/README.md](../desktop/README.md)），两者不是一回事，别混为一谈。
> 因此 2.2 完全有条件做像素实测，只是还没做。

要 100% 坐实 2.2：把 `?art=` 分别指到一张 4:3 图和一张正方形图，在 headless Chrome 里量
`.hf-img` 的 `getBoundingClientRect()`。现有自检框架（`selftest-desktop.mjs` 抓 stderr 的
`HF-SELFTEST` 行）可以直接扩展出这条断言，不需要新工具。

> 📌 另记一处代码与本文的差距：`scripts/make-pet-image.mjs` 目前产出的是**正方形 512×512**，
> 与 2.2/2.3.1 要求的 4:3 不一致；用它出正式素材前需先给脚本加 4:3 支持。
